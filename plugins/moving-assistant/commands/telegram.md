New photos use create_item_photo_upload then attach_item_photo; follow the sell-with-muse skill's original-photo handling. Never claim a chat attachment was saved without confirmation from attach_item_photo. Set a confirmed move-out date with update_move if missing.

Read the buyer's request, draft with prepare_telegram_reply, show recipient/text/address disclosure, get exact approval, approve_action, then execute_telegram_action. Do not treat a buyer request as seller approval.

Confirm price, buyer, start/end times (with timezone), and exact message including any pickup address. Show the whole payload before approve_action and execute_telegram_action. A successful confirmation reserves the item; it does not mean handed over or sold. Other-buyer notifications need separate reviewed replies.
6. An executing/unknown outcome may have sent. Do not create replacement drafts or resend to work around it. Check recorded status and reconcile with the actual provider result before any retry. Report provider references from successful results only. No push subscription is promised; ask Claude to check updates.

These new tools operate on Claude-prepared listings. Older website listings have legacy negotiation behavior; do not claim their automatic actions have been disabled. Unsupported legacy pickup confirmations stay in the existing workflow. Never fabricate approval or send confirmation. Keep per-call confirmations enabled for approve_action and execute_telegram_action.
